# 周视图拖拽排程页面设计（`public/design/schedule-week.html`）

## 背景

`public/design/` 目录已经是这个项目约定的"静态 HTML 设计稿"存放位置：先做一版可视化的静态/半交互 mockup，评审通过后再由这版 mockup 转换为真正的 Vue 组件并接后端（参考 `public/todo-development-steps.md` 记录的开发顺序，以及 `public/todo-quadrant.html` → `web/src/views/todo/TodoQuadrant/index.vue` 的先例）。

该目录下已有 `calendar-day.html` / `calendar-week.html`，但它们：
- 只是页面局部片段（注释里写明"需要外部拼上 `<head>`/`header`/`aside`"才能打开），不是可独立打开的完整页面；
- 时间轴只画到 8:00–18:00；
- 纯静态展示，没有拖拽选时间、没有创建待办的交互。

本设计新增一个**可独立打开、真正可交互**的周视图页面，用于"拖拽/多选一段时间 → 选优先级 → 加入待办"这个新流程，作为后续 Vue 化的参考稿。

## 范围

- **只做周视图**，不做月视图、不做独立日视图页面（用户明确排除）。
- **纯前端静态 mockup**：不调用真实后端 API，选择/创建行为只在页面内存状态里模拟，参考 `todo-quadrant.html` 早期做法。
- 新建文件 `public/design/schedule-week.html`，与现有 `calendar-week.html` 并存、互不影响；复用 `public/design/style.css` 的设计 token（颜色变量、`.button`、`.modal` 等通用类），但本文件本身是**完整独立**的 HTML（含 `<!DOCTYPE>`/`<head>`/`<body>`），可以直接双击/用浏览器打开预览，不依赖外部拼接。

## 页面结构

### 1. 顶部工具栏

沿用 `calendar-week.html` 已有的周导航样式（`‹` / `›` + "2026年 第32周 (8月3日 - 8月9日)"），额外增加：

- **粒度选择器**：`<select>`，选项 15min / 30min（默认） / 1hour。切换后重新渲染网格行数/行高。
- **模式切换**：两态按钮组"拖拽选择 / 多选格子"，决定网格单元格点击行为（见下）。
- **清空选择**：仅当已选中 ≥1 个格子时出现。

### 2. 时间网格

- 7 天列（周一～周日），当天列用 `--primary-light` 高亮（沿用 `calendar-week.html` 现有做法）。
- 行数由粒度决定：例如 30min 粒度 → 00:00–23:30 共 48 行。
- 左侧时间刻度只在整点显示文字标签，半点/其他粒度行只画分隔线，避免拥挤。
- 每个单元格：`<div class="slot-cell" data-day="1" data-time="09:30">`。
- 今天列上画一条细横线标出"当前时间"，仅作视觉参考，不参与交互逻辑。

### 3. 交互（两种模式，共享同一个 `selectedSlots` 数组作为数据模型）

- **拖拽模式**：`mousedown` 在某格开始拖拽；拖拽过程中 `mouseenter` 到的格子若与起点同一天列，则加入/移出选中范围（连续区间）；跨列的 `mouseenter` 不生效（拖拽限定在单天列内，用户已确认不需要跨天拖拽）。`mouseup` 直接弹出"创建待办"弹窗，预填这段连续区间。
- **多选格子模式**：普通 `click` 单独切换该格子的选中状态，可以跨天、跨时段任意勾选。因为没有"松手"这个天然触发点，提供一个"完成选择"按钮，点击后弹出"创建待办"弹窗。
- 选中格子实时显示一行小结，例如"已选 3 个时间段，合计 1.5 小时"。

### 4. 创建待办弹窗

字段与真实的 `TodoQuadrant.vue` 表单保持一致，方便未来直接复用同一套字段映射：

- **标题**：文本输入，必填。
- **象限/优先级**：4 个按钮，复用 `TodoQuadrant.vue` 里四象限的配色（红=紧急且重要、橙=紧急不重要、蓝=重要不紧急、灰=不紧急不重要），必选。不新增独立的"重要程度"/"优先级"字段——直接复用现有 `TodoItem.quadrant_type` 枚举，避免和后端模型脱节。
- **备注**：多行文本，选填。
- **已选时间段**（只读展示）：列出本次选中的所有时间段，例如"周三 09:00–09:30"，多段时逐条列出。
- **确定**：仅做前端模拟——在对应位置生成一个按象限配色的"事件块"渲染到网格里，关闭弹窗，不发起任何网络请求。

### 5. 视觉规范

- 复用 `public/design/style.css` 中的 CSS 变量（`--primary-color` 等）、`.button` / `.button-primary` / `.modal*` / `.form-control` 等通用类，保持与目录下其它设计稿视觉一致。
- 四象限配色直接从 `web/src/views/todo/TodoQuadrant/index.vue` 现有 CSS 搬过来（`#f5222d` / `#faad14` / `#1890ff` / `#909399`），避免以后转 Vue 组件时颜色对不上。

## Mockup 已知边缘问题（评审已确认，留给 Vue 化时处理）

最终代码评审确认以下 Minor 级边缘问题存在于静态稿中，均不影响 mockup 演示，Vue 化时一并解决：

- `schedule-week.html`：事件块未设 `pointer-events: none`，拖拽经过已有事件块处选区停止扩展（Vue 化时加上或改用列级事件委托）
- `schedule-week.html`：鼠标移出浏览器窗口松开时 `mouseup` 不触发，拖拽状态粘滞到下一次点击
- `schedule-week.html`：选区小结用 `toFixed(1)`，15 分钟粒度下 0.25 小时显示为 0.3
- `calendar-day.html`：拖放到 23:30 之后的格子会生成越过午夜的事件块（需对起始分钟做 `[0, 1380]` 钳制）
- `calendar-day.html`：无 `dragend` 清理，取消的拖拽会残留待放置状态

## 已知缺口（不在本次范围内，留给后续 Vue 化时处理）

后端 `TodoItem` 模型（`app/models/todo.py`）目前只有单个 `due_date` 字段，没有开始/结束时间。也就是说这个 mockup 里"拖拽出一段时间范围"这个概念，暂时无法 1:1 映射到现有 API。真正把这个页面接入后端时，需要先给 `TodoItem`（或新表）加上开始时间/结束时间字段并迁移数据库——这次的 mockup 只负责把交互和视觉钉下来，不改后端。

## 验收标准

- `public/design/schedule-week.html` 可以直接用浏览器打开，无需其它文件拼接（`style.css` 除外，作为 `<link>` 引入）。
- 支持 15/30/60 分钟三种粒度切换，网格随之重新渲染。
- 拖拽模式下能在单日列内连续选中/取消一段时间；多选模式下能跨天勾选任意不连续格子。
- 选中后能弹出表单，填写标题+选象限+备注后"确定"，网格上出现对应颜色的事件块。
- 不依赖真实后端接口，纯前端状态模拟。
