# 四象限待办事项功能开发步骤

## 开发步骤与提示词

### 第1步：创建后端模型

```
提示词：请在app/models目录下创建todo.py文件，定义四象限待办事项功能所需的模型。我需要一个TodoItem模型，包含以下字段：
- 标题(title)：字符串类型
- 象限类型(quadrant_type)：枚举类型，包括四种象限：紧急且重要、紧急但不重要、重要但不紧急、不紧急也不重要
- 截止日期(due_date)：日期类型，可为空
- 是否已完成(is_completed)：布尔类型
- 完成时间(completed_at)：日期时间类型，可为空
- 用户ID(user_id)：与现有用户关联

请确保模型继承自BaseModel和TimestampMixin，以获取id和创建/更新时间字段。
```

### 第2步：更新模型初始化文件

```
提示词：请在app/models/__init__.py中导入新创建的待办事项模型，确保它能被系统正确加载。
```

### 第3步：创建API结构体

```
提示词：请在app/schemas目录下创建todo.py文件，定义待办事项相关的Pydantic模型，包括：
- TodoItemCreate：创建待办事项的请求体
- TodoItemUpdate：更新待办事项的请求体
- TodoItemOut：待办事项的响应体
- TodoStatisticsByDate：按日期统计的待办事项数量
- QuadrantStatistics：按象限统计的待办事项数量

这些结构体将用于API请求和响应的数据验证。
```

### 第4步：创建API路由

```
提示词：请在app/api/v1目录下创建todos目录，并添加__init__.py和route.py文件，实现以下API端点：
- GET /todos：获取所有待办事项，支持按象限和完成状态筛选
- POST /todos：创建新的待办事项
- GET /todos/{todo_id}：获取指定ID的待办事项
- PUT /todos/{todo_id}：更新指定ID的待办事项
- DELETE /todos/{todo_id}：删除指定ID的待办事项
- GET /todos/statistics/daily：获取按日期统计的已完成待办事项数量
- GET /todos/statistics/quadrant：获取按象限统计的待办事项数量

确保所有API都需要用户认证，并且只能操作当前登录用户的待办事项。
```

### 第5步：注册API路由

```
提示词：请在app/api/v1/__init__.py中注册待办事项路由，将其添加到v1_router中。确保路由前缀为"/todo"，并添加依赖项以确保API访问需要登录。
```

### 第6步：数据库迁移

```
提示词：请执行数据库迁移，将新创建的TodoItem模型添加到数据库中。如果项目使用的是Tortoise ORM的自动迁移，请确保迁移脚本能正确生成待办事项表。
```

### 第7步：前端API服务

```
提示词：请在web/src/api目录下创建todo.js文件，实现与后端API的通信，包括：
- getTodos：获取待办事项列表，支持筛选
- createTodo：创建新待办事项
- updateTodo：更新待办事项
- deleteTodo：删除待办事项
- getDailyStatistics：获取每日统计数据
- getQuadrantStatistics：获取象限统计数据

请确保使用项目统一的API请求方式和错误处理机制。
```

### 第8步：创建前端状态管理

```
提示词：请在web/src/store/modules目录下创建todo.js文件，实现待办事项的状态管理，包括以下功能：
- state：存储待办事项列表和统计数据
- mutations：更新状态的方法
- actions：异步获取和修改数据的方法
- getters：计算属性，如按象限分组的待办事项

确保正确注册此模块到主store中。
```

### 第9步：创建四象限待办页面组件

```
提示词：请在web/src/views目录下创建todo目录，并添加TodoQuadrant.vue组件，实现四象限待办事项页面，包括：
- 四象限布局，每个象限显示对应类型的待办事项
- 新建待办按钮和表单
- 待办事项卡片，支持标记完成、移动到其他象限和删除操作
- 待办事项卡片显示标题、创建时间和截止日期等信息

请确保与之前的设计图保持一致，使用项目的UI框架和样式系统。
```

### 第10步：创建历史统计页面组件

```
提示词：请在web/src/views/todo目录下创建TodoHistory.vue组件，实现历史统计页面，包括：
- 日期范围选择器，用于筛选特定时间段的数据
- 使用图表库(如ECharts或Chart.js)展示每日完成待办数量的堆叠柱状图
- 使用饼图展示四象限待办分布
- 已完成待办的列表，支持分页和排序

请确保与之前的设计图保持一致，使用项目的UI框架和样式系统。
```

### 第11步：添加路由配置

```
提示词：请在web/src/router目录下的路由配置文件中添加待办事项相关路由，包括：
- /todo/quadrant：四象限待办页面
- /todo/history：历史统计页面

确保路由配置包含正确的组件引用、路由元数据(如菜单信息)和认证要求。
```

### 第12步：添加菜单配置

```
提示词：请在菜单配置中添加待办事项相关菜单，确保用户可以从侧边栏访问四象限待办页面和历史统计页面。如果需要，添加适当的图标和权限设置。
```

### 第13步：国际化支持(可选)

```
提示词：如果项目支持多语言，请在国际化文件中添加待办事项相关的文本翻译，包括菜单名称、按钮文本、提示信息等。
```

### 第14步：测试和调试

```
提示词：请测试待办事项功能，确保前后端正常通信，数据能正确保存和展示。修复发现的任何问题。
```

## 实现顺序建议

为了高效开发，建议按照以下顺序实施上述步骤：

1. 先完成后端开发(步骤1-6)：创建模型、API结构体和路由
2. 测试后端API是否正常工作
3. 再进行前端开发(步骤7-12)：API服务、状态管理、组件和路由
4. 最后进行集成测试和调试
